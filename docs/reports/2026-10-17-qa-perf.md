# Apeiron QA and Performance Report

Date: 2026-10-17
Scope: accessibility and performance evidence for the M5 milestone of the roadmap-completion plan.

## Scope

This report covers the accessibility and performance posture of the shipped surfaces:
the Cosmic Journey, the Explorer and its topic pages, Cosmic Today, the Calculators,
and the Numbers / Cosmic Calendar content pages. Every claim below is checkable in the
source tree or in a named unit test. End-to-end tests and real-device Web Vitals
numbers are out of scope for this milestone (the plan skips e2e by request); both are
recorded under Open issues and follow-ups.

## Accessibility

Source of truth for the motion and color decisions is `docs/design/design-plan.md`.

### Keyboard and focus

- Every interactive control is a real `button` or `a` element, never a click handler on
  a `div`. `Button` renders an `a` when `href` is given and a `button type="button"`
  otherwise (`src/components/ui/Button.tsx`), asserted in `tests/unit/ui-states.test.tsx`
  ("Button renders an anchor when href is given", "Button renders a button when no href").
- Minimum target size is enforced in the same component via `min-h-11 min-w-11`
  (44px), and the motion toggle uses `min-h-9` (36px) on a text control
  (`src/components/ui/Button.tsx`, `src/components/ui/MotionToggle.tsx`).
- The journey progresses with plain scroll, so no keyboard trap is introduced by the
  pinned path. The reduced-motion path is deliberately "completable by plain scroll and
  keyboard" and renders the stages stacked in normal flow
  (`src/features/cosmic-journey/CosmicJourney.tsx`, reduced branch).
- The stage-progress control is a labelled list where each step exposes
  `aria-current="step"` on the active item and an `sr-only` copy of the stage's
  accessible label, so a screen reader announces position without relying on the
  visible digit (`src/features/cosmic-journey/JourneyProgress.tsx`).

### Semantics

- Decorative layers are hidden from assistive tech: the sky gradient, the canvas, and
  the scroll-progress ruler are all `aria-hidden="true"`
  (`src/features/cosmic-journey/CosmicJourney.tsx`, `JourneyStage.tsx`, `ScaleRuler.tsx`).
- The scale ruler is meaningful, not decorative, so it carries a computed `aria-label`
  naming the current order of magnitude (`src/features/cosmic-journey/ScaleRuler.tsx`).
  The numeric readout next to it is decorative and hidden, because the same value is
  already announced by the ruler label (`src/features/cosmic-journey/ScaleReadout.tsx`).
- Loading and error states announce through roles: `LoadingState` uses `role="status"`
  and `ErrorState` uses `role="alert"`
  (`src/components/ui/LoadingState.tsx`, `ErrorState.tsx`), asserted in
  `tests/unit/ui-states.test.tsx` ("LoadingState announces politely",
  "ErrorState announces as alert").
- Images carry descriptive alternative text. `PlanetImage` sets `alt` from the entry's
  `altText` and falls back to a `role="img"` labelled container when the source fails
  (`src/features/explorer/PlanetImage.tsx`). The registry guarantees every planet image
  has alt text and credit (`tests/unit/planet-images.test.ts`).

### Reduced motion

- One source of truth, `src/lib/motion-preference.ts`, resolves the OS
  `(prefers-reduced-motion: reduce)` setting and a stored per-device choice; the OS
  setting always wins (`getCalm`).
- The served-first render is the reduced, no-JS-readable journey: the server snapshot
  is `true`, so users see the static, scrollable version before hydration and only
  upgrade to the pinned experience once the client confirms motion is allowed
  (`src/features/cosmic-journey/CosmicJourney.tsx`).
- The heavy canvas scene and its animation loop are never imported or started in the
  reduced branch, so reduced users pay no scene cost
  (`src/features/cosmic-journey/CosmicJourney.tsx`, both effects early-return on
  `reduced`).

### Color and non-color signals

- The palette is closed at four core tokens plus one accent, plus the functional
  `--line` hairline (`docs/design/design-plan.md`), asserted in
  `tests/unit/tokens.test.ts` ("defines the four mandated colors exactly").
- Fact confidence is rendered as text, never color alone
  (`src/components/ui/DataLabel.tsx`), asserted in `tests/unit/ui-states.test.tsx`
  ("DataLabel shows value, unit, and a text status from the dictionary").

## Performance

### Dynamic imports in use

- The Cosmic Journey's canvas scene is lazy-loaded with `await import("./scene/scene")`
  inside an effect, only in the motion branch. The CSS gradient and star fallback
  always render, so a failed import or missing 2D context still leaves the journey
  visible (`src/features/cosmic-journey/CosmicJourney.tsx`,
  `src/features/cosmic-journey/scene/scene.ts`). This keeps the drawing code out of the
  initial bundle for reduced-motion and no-JS readers.

### Adaptive rendering quality

- `quality()` in the scene caps device pixel ratio to 1 and reduces star, blob,
  galaxy, and arm counts on weak devices (`navigator.hardwareConcurrency <= 4`) or
  narrow viewports (`innerWidth < 768`); otherwise dpr caps at 2 and full counts are
  drawn (`src/features/cosmic-journey/scene/scene.ts`). One factor, one place.
- A missing 2D context returns a no-op scene handle so the fallback stays live rather
  than throwing (`src/features/cosmic-journey/scene/scene.ts`).

### Font loading

- All three faces load through `next/font/google` with `display: "swap"` and are
  exposed as CSS variables (`src/app/fonts.ts`), so text paints immediately in a
  fallback face and swaps when webfonts arrive. Self-hosting via `next/font` also
  removes a third-party font connection from the critical path.

### Image handling

- Explorer imagery uses plain `img` with an explicit `onError` fallback and a fixed
  `aspect-[4/3]` box, so a failed or slow image cannot shift layout and degrades to an
  accessible placeholder (`src/features/explorer/PlanetImage.tsx`). NASA Image Library
  responses are validated through a schema before use and cached, so the UI never reads
  a raw provider shape (`src/lib/astronomy/providers/nasa-images.ts`,
  `src/lib/cache/ttl-cache.ts`).

### Measurement hook

- `WebVitalsReporter` is mounted once in the root layout inside `<body>`. It registers
  CLS, LCP, and INP on mount and logs each as
  `[web-vitals] name=... value=...` via a structured console line, and renders nothing
  (`src/components/perf/WebVitalsReporter.tsx`, `src/app/layout.tsx`), asserted in
  `tests/unit/web-vitals.test.tsx` ("registers the three metrics without rendering
  anything"). This is the hook that will surface field numbers once real-device
  collection is wired.

## Bundle notes

- `web-vitals@6.2.3` is added as a runtime dependency and imported only by the
  client-side reporter that renders `null`; it does not affect the server render tree
  (`package.json`, `src/components/perf/WebVitalsReporter.tsx`).
- The scene module is the largest optional client chunk and is excluded from the
  reduced-motion path by the conditional dynamic import described above.
- No new decorative assets or palette entries were introduced.

## Open issues and follow-ups

- Automated accessibility (axe) is not yet wired. `tests/e2e/a11y.spec.ts` exists
  (keyboard and WebGL-disabled checks) but is not axe-based. The plan skips e2e, so the
  follow-up is to add axe scanning to that spec over the journey, explorer, and topic
  pages once e2e is re-enabled.
- Real-device Web Vitals are pending. The reporter logs to the console today; wiring a
  beacon to a collector is the follow-up that turns it into field data.
- Image delivery still uses plain `img` rather than `next/image`; the fixed aspect box
  prevents shift, but automatic `srcset` and lazy loading remain a future improvement.
